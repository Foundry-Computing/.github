# Support

## Where to ask for help

- Use the relevant repository's issue tracker for reproducible defects,
  approved feature work, documentation requests, and project tasks.
- Use pull requests for focused review of proposed changes.
- Use repository or organization discussions when they are enabled for the type
  of conversation needed.

## Before opening an issue

- Search existing issues first.
- Include affected repository or product, version or commit, expected behavior,
  actual behavior, and sanitized diagnostics.
- Do not include credentials, personal data, private file paths, raw secret
  material, or confidential project information.

Security reports follow `SECURITY.md` and must not be filed as public support
issues.
